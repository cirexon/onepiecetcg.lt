The site has no analytics SDK, advertising SDK, payment flow, upload feature, messaging feature, or password-authentication provider. It makes first-party Hosting requests, Firebase/Google Authentication and Firestore requests, and user-initiated links to the official game website and Discord.

## Client storage and consent classification

`op-lang` and `op-theme` are functional preferences. Firebase authentication storage is essential when a user chooses to sign in. No non-essential tracking is implemented, so the current application does not display a tracking-consent banner. Reassess this decision before adding analytics, embeds, advertising, session replay, or marketing technology.

## Processor and transfer record

Google/Firebase provides Hosting, Authentication, Firestore, and operational service data processing. Before launch, the controller must record acceptance of the applicable Firebase and Google Cloud data-processing terms, review the current subprocessor list and transfer mechanism, and retain the review date. GitHub stores source code; production personal data must not be copied into issues, commits, or test fixtures.

## Data-subject request workflow

1. Receive the request through the public privacy contact that still needs to be selected.
2. Verify identity without requesting unnecessary identity documents; for an account request, use the signed-in Google identity where possible.
3. Log the request date, scope, identity check, owner, deadline, actions, and response without copying more personal data than necessary.
4. Search Firebase Authentication, `accounts`, `roles`, `players`, tournaments/results, news attribution if introduced, and relevant restricted logs.
5. Correct, export, restrict, object to, delete, or pseudonymise data as legally required; test that public profiles and statistics update.
6. Respond within the applicable deadline and retain minimal proof of completion.

This workflow has not completed a tabletop request. DOC-07 remains blocked until the contact, legal decisions, and one evidenced exercise are complete.

## Decisions required before real participant data

- Identify the controller and publish a privacy contact and complaint route.
- Approve a lawful basis for account administration, public results, and player histories.
- Define how organisers record permission or another defensible basis before publishing a player.
- Approve retention, deletion, correction, objection, and portability handling.
- Decide how minors may appear in results and whether guardian involvement is required.
- Record processor terms, transfers, DPIA screening, and the owner/date of each review.
